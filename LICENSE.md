# Licensing

**`pkpd-data` is a data aggregation repository.** It does not relicense anything
it redistributes. Each dataset keeps the license it arrived under; this repo
adds only a curation layer (manifest, provenance records, checksums, docs) on
top.

There is deliberately **no single top-level `LICENSE` file**, because no single
license could be accurate. The corpus contains material under GPL-2.0-only,
GPL-3.0-or-later, CC0-1.0 and CC-BY-4.0. GPL-2.0-only and GPL-3.0-or-later are
mutually incompatible *in a combined work*, but coexist without conflict as mere
aggregation — which is precisely what this repository is, and why the
aggregation framing is the correct one rather than a convenience.

Licensing is declared per file in [`REUSE.toml`](REUSE.toml), following the
[REUSE Specification 3.3](https://reuse.software/spec-3.3/). Full license texts
are in [`LICENSES/`](LICENSES/).

## How it is recorded, and how to check it

Two layers, deliberately separate. `REUSE.toml` is the machine-readable per-path
declaration a downstream tool reads. A `PROVENANCE.yaml` in each dataset
directory is the human-readable record of *why* that declaration is what it is —
where the file came from, who checked, on what date, against what evidence.
`"unknown"` is a valid value in those records; guessing is not.

```bash
pip install reuse pyyaml
reuse lint                        # every file has declared licensing
python tools/check_provenance.py  # every dataset has a complete record
python tools/checksums.py --check # content matches CHECKSUMS.sha256 and the records
```

All three run in CI on every push and pull request
([`.github/workflows/licensing.yml`](.github/workflows/licensing.yml)).
Unresolved licenses are *reported without failing* — they are a tracked state,
not a regression. A missing or incomplete record does fail: a dataset quietly
appearing with no stated origin is how aggregation repositories accumulate
legal debt.

**A record covers a directory tree, not a directory**, since one dataset can span
several levels — ggPMX's theophylline spans `ggpmx/`, `ggpmx/Monolix/` and
`ggpmx/Monolix/ChartsData/Saem/` under one license. The corollary is that a
directory must not mix licenses, which is why `data/pk_pd/warfarin/` was split
into `nlmixr2data/` (GPL-3.0-or-later) and `monolix/` (unresolved): `REUSE.toml`
could express two licenses in one directory, but a per-directory provenance
record cannot. The loose `semimech_antibiotics` files were moved into their own
directory for the same reason — a record sitting at `data/pk_pd/` would silently
adopt any future dataset dropped there without one.

no data and is derived from none, so it inherits nothing.

## Challenge-owned data is CC0

`QIC2025-EstDat.csv` and `UpdatedEstData.csv` are synthetic, generated by the
challenge organisers, and released under
[CC0-1.0](https://creativecommons.org/publicdomain/zero/1.0/) — public domain
dedication, no attribution required (though citation is appreciated).

This choice is not merely permissive-by-default. Whether model weights trained
on copyleft-licensed data constitute a derivative work of that data is unsettled
in every jurisdiction. CC0 removes the question entirely, which is what makes
the challenge datasets the preferred basis for any **publishable blind
evaluation**. Treat the GPL-licensed sets as development and validation material.

The DDMoRe material is CC0 too and can serve the same purpose, but only
ciprofloxacin's CC0 status is *confirmed* — see below. If a blind evaluation has
to rest on data whose license is beyond argument, rest it on the challenge's own
synthetic data, which the organisers generated and therefore control outright.

`QIC2025-EstDat.csv` was previously served only from
`quantum-challenge.eu/assets/` and was absent from this repository. It is now at
`data/qic/QIC2025-EstDat.csv` (sha256 `100f8829…`), so the CC0 dedication
attaches to a file under version control and the whole corpus is checksummed in
one place.

## What aggregation does and does not solve

It **does** resolve the combination problem: incompatible copyleft licenses can
sit side by side in one repository, because no combined or derivative work is
formed by placing files in adjacent directories.

It **does not** grant redistribution permission for any individual file. Hosting
a dataset in an aggregation repository is still redistribution of that dataset.
Three items were open on that basis; one has since been closed.

**Closed by deletion.** `data/pk_pd/warfarin/monolix/warfarin_data.txt`
(a MonolixSuite demo encoding) was removed on 2026-08-08. It was the same
O'Reilly 1968 study data as the GPL-3 `warfarin.rda` next door — verified by
reading both, with `time`, `wt` and `age` matching row-for-row across all 515
rows and only cosmetic encoding differences. Deleting it cost a column-name
mapping (recorded in `data/pk_pd/warfarin/nlmixr2data/PROVENANCE.yaml`) and
nothing else, which beat spending a legal conversation on it.

Two remain:

1. **remifentanil `.xls`** (Monolix demo dataset). Lixoft / Simulations Plus
   documentation is proprietary; whether the demo *datasets* may be redistributed
   has not been established. Unlike warfarin there is no license-clean substitute
   — it is not in nlmixr2data, PKPDdatasets or the DDMoRe mirror — and
   `pharmaceutiq` is built on it, so deleting is not free.

   **There is a better party to ask than Simulations Plus.** The same 65 subjects
   are published by the study's own authors through the Open TCI Initiative
   ([opentci.org](http://opentci.org/data/remifentanil/minto-1997-study)) as
   `minto_remi.zip`, an archive of Steven Shafer's PK/PD software server holding
   `server/comp_pk/REMI.DAT` (PK) and `server/comp_pd/KE0DATA.TXT` (EEG effect).
   Verified 2026-08-08 as the same subjects: AGE and LBM match per subject id
   across all 65. Open TCI states no license either, so this is not a drop-in
   fix — but Minto, Schnider and Shafer are the rights holders in the underlying
   data and they run Open TCI precisely to share it. Ask them for an explicit
   CC0/CC-BY statement and re-source the file from `REMI.DAT`.
2. **moxifloxacin**, attributed in the README to a personal Naver blog post.
   **Now traced** (2026-08-08), from evidence that was inside the control stream
   all along: it names its author (Sebastian G. Wicha), its THETAs
   (CL 12.1, V1 68.1, Q 20.3, V2 44.6 L) reproduce the published final estimates
   exactly, its covariate structure (IBW<sup>0.75</sup> on CL, weight on V1/V2)
   is the published model, and its 50 subjects match the 50 patients enrolled in
   Wicha SG, et al., *J Clin Pharmacol* 2015;55(6):639-46. So there is now a
   named academic to ask — a tractable request in a way a blog post never was.
   An identifiable author is still not a grant, so the status is unchanged.

Until resolved, both are tagged `LicenseRef-Unresolved-*` in `REUSE.toml`, given
placeholder texts in `LICENSES/` that state plainly that they are not licenses,
and reported (without failing) by `tools/check_provenance.py` — visible rather
than silently assumed.

## The DDMoRe attributions, checked

Four datasets were annotated CC0 on the strength of "looks like a DDMoRe Model
Repository entry". That was checked on 2026-08-08 against the
[`dpastoor/ddmore_scraping`](https://github.com/dpastoor/ddmore_scraping) mirror
(641 files, 60 entries), and the four do not stand equally:

| Dataset | Result |
|---|---|
| ciprofloxacin | **Confirmed.** Both files byte-identical (sha256) to entry 225 |
| bedaquiline | **Downgraded.** Attributed to entry 219, but 219 is a *different* Svensson model and these files are in no entry |
| tcell mAb | Unconfirmed. Not in the mirror; the `.mod` names no author and no study |
| semimech antibiotics | Unconfirmed. Not in the mirror, but the `.mod` names its study (Nielsen 2007) |

The bedaquiline result is the one to note, because it moved in the wrong
direction: it was the dataset with the most confident-looking provenance record
in the repo. Entry 219 is `BDQ_M2_PK_plus_WT_ALB_in_MDR-TB_patients` — Svensson's
time-varying weight and albumin model — not the LPV/RTV interaction dataset held
here. The citation in its record was wrong for the same reason (it named the 2013
efavirenz paper; the control stream describes lopinavir/ritonavir, i.e.
*AAC* 2014;58(11):6406). Both are corrected in its `PROVENANCE.yaml`. Nothing is
blocked — the naming convention remains decent evidence — but "verified" was not
an accurate word for it.

**`repository.ddmore.foundation` returned HTTP 503** when checked. The CC0 basis
for all of this material is that repository's terms of use, which currently
cannot be re-read at source; the mirror is what the confirmations rest on. If the
repository is gone for good, these attributions can never be upgraded past what
is recorded now — which is an argument for preferring challenge-owned data for
anything publishable, and for capturing evidence while mirrors still exist.

**The general lesson: the provenance was inside the model files the whole time.**
Every `.mod` in the corpus except the T-cell one names either its author or its
source publication in a header comment or `$PROBLEM` line, and moxifloxacin's
even carries parameter estimates that can be matched against the published paper.
The README's list of upstream URLs was the weakest available evidence, and it was
the only place anyone had looked. When a new dataset arrives, read its control
stream before writing its record.

## Downstream obligations

- **CC0 material** — use freely, including commercially, no conditions.
- **GPL-3.0-or-later** and **GPL-2.0-only** — the license text must accompany
  redistribution, and copyright notices must be preserved. `REUSE.toml` plus
  `LICENSES/` satisfies this for anyone who copies the tree wholesale.
- **Do not vendor GPL-2.0-only material into `qic-pkpd-core`** (Apache-2.0) or
  into any GPL-3 work. Read the file formats directly rather than linking the
  GPL R packages: parsing a `.rda` file is not linking `nlmixr2data`; calling
  into R via `rpy2` to load it may be.
- **Note on EU law.** Beyond copyright, the EU *sui generis* database right
  (Directive 96/9/EC) can protect substantial investment in obtaining,
  verifying or presenting a database, for 15 years, independently of whether
  the individual data points are copyrightable. "It's just numbers" is a weaker
  argument in Europe than in the US. The CC0 dedication on challenge-owned data
  waives database rights as well as copyright.
